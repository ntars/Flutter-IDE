# 文档贡献说明

> 完整的贡献流程（DCO 签名、提交纪律、CLA 保留条款）见仓库根目录的
> [CONTRIBUTING.md](../CONTRIBUTING.md)。本文档只说 docs/ 目录自己的规矩。

## 四份文档的分工

| 文档 | 写什么 | 不写什么 |
|---|---|---|
| `architecture.md` | 分层契约、依赖方向、数据流、AI 铁律 | 字段表（那是 schema 文档的事） |
| `intent-schema.md` | 意图大纲与覆盖层的全部字段、校验规则 | 实现细节 |
| `block-protocol.md` | 物料协议全字段、类型表、贡献流程 | 校验规则（那是 schema 文档的事） |
| `contributing.md` | docs/ 目录自己的规矩 | 通用贡献流程（指回根目录） |

两条分界：**字段进 schema，流程进 protocol，架构只说边界**。文档重复
不是冗余，是两处事实将来不同步的入口。

## 写作纪律

1. **数字要有出处。**「960×600」「40% 阈值」这类值要说明来源（实测 / 上游
   规范 / 方案第几节），不写无出处的数。
2. **取舍要写理由。**「为什么不是 X」一节比「是什么」一节更值得写——
   X 以后还会被重新提出来，理由写下来就不用第三次论证。
3. **示例即契约。** 文档里的 YAML 示例必须能通过校验器；改了 schema 而没改
   示例的 PR 会被要求补。
4. **中文为主，代码与字段名保留原文。**
